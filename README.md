# Garam

C++로 제작한 2D 액션 플랫포머 게임 — 4명의 보스와 다양한 아이템 제작 시스템을 갖춘 학교 팀 프로젝트.

![C++](https://img.shields.io/badge/language-C%2B%2B-blue) ![SFML](https://img.shields.io/badge/library-SFML%202.5.1-green)

## Features

- **4개의 고유 보스 전투** — 각 보스마다 독립적인 공격 패턴(돌진, 원거리 투척, 화염, 수중 이동 등)을 가진 상태 머신 기반 AI
- **다중 스테이지** — 숲, 동굴, 화산, 신전 등 배경과 지형이 다른 여러 구역으로 구성
- **인벤토리 & 아이템 제작** — 재료 수집 후 레시피에 따라 회복 아이템·버프 아이템·장비를 조합하는 크래프팅 시스템
- **커스텀 애니메이션 시스템** — `.anm` / `.spt` 파일 기반의 스프라이트 시트 애니메이션으로 캐릭터·적·보스 동작 처리
- **GLSL 셰이더 효과** — 이펙트 레이어에 GLSL 셰이더를 적용해 시각적 연출 추가

## Built With

- **C++** — 게임 로직 전체(캐릭터, 보스, 충돌, 카메라, 인벤토리)를 구현하는 주 언어로 사용
- **SFML 2.5.1** — 창 생성·2D 렌더링·오디오 재생을 한 라이브러리로 처리할 수 있어 채택; DLL이 저장소에 포함되어 별도 설치 불필요
- **GLSL** — 런타임 셰이더 효과를 CPU 코드와 분리해 관리하기 위해 사용
- **CMake** — 크로스 플랫폼 빌드 구성 지원

## Getting Started

### Prerequisites

- Windows
- Visual Studio 2019 이상 (MSVC 컴파일러)
- SFML 2.5.1 — `Lib/SFML-2.5.1/` 및 프로젝트 루트의 DLL 파일이 저장소에 포함되어 있으므로 별도 설치 불필요

### Installation

```bat
git clone https://github.com/Git-Mere/Garam.git
cd Garam
```

### Build & Run

Visual Studio에서 솔루션 파일을 열어 빌드한다.

```bat
# Visual Studio로 열기
start Gam_150_project\Gam_150_project.sln
```

1. Visual Studio에서 솔루션이 열리면 빌드 구성을 **Release** 또는 **Debug**로 선택한다.
2. **빌드 → 솔루션 빌드** (Ctrl+Shift+B)를 실행한다.
3. 빌드된 실행 파일을 실행한다. SFML DLL 파일은 프로젝트 디렉터리에 이미 포함되어 있다.

## What I Learned

**보스 AI 상태 머신 설계**

보스 4개를 각각 독립적인 `.cpp`/`.h`로 분리하면서, 처음에는 단순 플래그 변수로 상태를 관리했다. 돌진·대기·공격 패턴이 중첩되자 조건문이 기하급수적으로 늘어났고, 한 보스의 패턴을 수정하면 다른 곳에서 버그가 터지는 상황이 반복됐다. 이후 각 보스에 명시적인 열거형 상태와 전환 조건을 도입해 상태별 진입·유지·탈출 로직을 분리했고, 그 결과 Boss2의 낙하 공격(`fall_attack.anm`)과 에너지 투척(`throw_energy.anm`)을 독립적으로 튜닝할 수 있었다.

**커스텀 애니메이션 파이프라인 구축**

SFML은 스프라이트 시트를 잘라 표시하는 기능만 제공한다. 프레임 타이밍·루프 여부·이벤트 트리거를 캐릭터·적·보스 전반에서 재사용하려면 별도 시스템이 필요했다. `.anm` 파일 포맷을 정의하고 `animation.cpp`로 파싱·재생 로직을 캡슐화한 뒤, 각 객체가 애니메이션 컴포넌트를 참조하도록 구조를 잡았다. 이 구조 덕분에 Boss3의 텔레포트(`teleport_pattern.anm`)처럼 복잡한 다단계 이펙트도 애니메이션 파일 교체만으로 조정할 수 있었다.

**인벤토리·크래프팅 데이터 설계**

30종 이상의 아이템(재료·소비·장비)을 하드코딩 없이 관리하기 위해 `ItemTable.h`에 데이터 테이블을 두고 `recipe.txt`로 제작 규칙을 외부에서 정의하는 구조를 택했다. 아이템 추가 시 코드 수정 없이 테이블과 레시피 파일만 편집하면 됐고, 이 경험으로 게임 데이터와 로직 코드를 분리하는 것의 실질적인 이점을 직접 확인했다.
